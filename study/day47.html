데이터베이스 개요 — 데이터를 모아 두는 창고

2026-08-19 · 오늘 배울 개념 5개 + 퀴즈 10문제 (약 1시간)

복습 한 스푼 🥄

어제(Day 46)는 오버플로 해결법과 파일 구조를 배웠어요. 딱 하나만 다시: 개방 주소법은 빈 옆자리를 찾아가고, 체이닝은 연결 리스트를 매단다. 그리고 색인 순차 파일은 순차 접근과 직접 접근이 모두 가능했죠. 오늘은 그 파일들을 체계적으로 관리하는 데이터베이스를 만납니다. 3과목에서 본격적으로 다룰 내용의 뼈대예요.

1. 데이터베이스란? — 파일을 따로따로 두면 벌어지는 일

예전에는 부서마다 파일을 따로 만들어 썼어요. 영업부는 영업용 고객파일, 회계부는 회계용 고객파일을 각자 관리하는 식이죠. 이 방식의 문제가 데이터베이스가 태어난 이유입니다.

파일 따로 관리의 문제무슨 일이 생기나
데이터 중복같은 고객 정보가 여러 파일에 반복 저장 → 저장 공간 낭비
데이터 불일치영업부에서 주소를 바꿨는데 회계부 파일은 옛 주소 → 어느 게 맞는지 모름
데이터 종속파일 구조를 바꾸면 그 파일을 쓰는 프로그램을 전부 수정해야 함

데이터베이스(DB)는 이런 문제를 해결하기 위해 여러 사람이 공동으로 사용할 데이터를 중복 없이 한곳에 모아 통합 관리하는 저장소예요.

데이터베이스의 4가지 성질 (시험 단골!) — ① 통합된 데이터(중복을 최소화해 모음) ② 저장된 데이터(컴퓨터 저장장치에 보관) ③ 운영 데이터(조직 운영에 꼭 필요한 데이터) ④ 공용 데이터(여러 사용자가 함께 씀). "통·저·운·공"으로 외우세요.
시험 포인트 — DB의 4대 특성(통합·저장·운영·공용)과, DB가 해결하는 3대 문제(중복·불일치·종속)가 각각 한 문제씩 나옵니다.

2. DBMS — 데이터베이스를 관리해 주는 프로그램

DBMS(DataBase Management System, 데이터베이스 관리 시스템)는 사용자와 데이터베이스 사이에서 모든 요청을 중개해 주는 소프트웨어예요. 오라클, MySQL, MS-SQL, PostgreSQL이 모두 DBMS입니다.

비유 — 데이터베이스가 거대한 창고라면 DBMS는 창고 관리인이에요. 물건을 직접 뒤지지 않고 관리인에게 "3번 선반 물건 주세요"라고 요청하면 되죠. 관리인은 아무나 못 들어오게 막고(보안), 두 사람이 같은 물건을 동시에 가져가지 못하게 조정하고(병행 제어), 사고가 나면 원상복구(회복)까지 합니다.

DBMS의 3대 필수 기능은 반드시 외워야 합니다.

기능하는 일관련 언어
정의 기능
(Definition)		데이터의 구조와 형식을 정하는 일 (표를 만들고 바꾸고 지움)DDL (CREATE·ALTER·DROP)
조작 기능
(Manipulation)		데이터를 넣고·찾고·바꾸고·지우는 일DML (SELECT·INSERT·UPDATE·DELETE)
제어 기능
(Control)		정확성과 보안을 유지하는 일 (권한 부여, 무결성, 병행 제어)DCL (GRANT·REVOKE·COMMIT·ROLLBACK)
시험 포인트 — "DBMS의 필수 3기능은?" → 정의·조작·제어. 그리고 각각에 대응하는 언어(DDL·DML·DCL)까지 묶어서 나옵니다.

3. DBMS의 장점과 단점

장점단점
데이터 중복과 불일치를 줄인다DBMS 자체가 비싸고 전문 관리 인력(DBA)이 필요
데이터 독립성 — 저장 구조를 바꿔도 프로그램을 안 고쳐도 됨자료 처리 방법이 복잡해지고 시스템 부담(오버헤드)이 커짐
무결성·보안을 중앙에서 관리한곳에 모여 있어 장애가 나면 피해가 전체로 번짐
여러 사용자가 동시에 공용으로 사용백업·회복 절차가 까다로움
DBA(데이터베이스 관리자) — 데이터베이스를 설계하고, 사용자 권한을 나눠 주고, 성능을 손보고, 백업을 챙기는 사람이에요. 창고 관리인을 부리는 총괄 책임자라고 보면 됩니다.
시험 포인트 — 데이터 무결성(Integrity)은 "데이터가 정확하고 일관되게 유지되는 성질", 보안(Security)은 "허가받은 사람만 접근하게 하는 것". 두 단어를 바꿔치기한 보기가 자주 나옵니다.

4. 스키마 — 데이터베이스의 설계도 3장

스키마(Schema)는 데이터베이스의 구조와 제약조건을 적어 둔 설계도예요. 보는 사람의 입장에 따라 3단계로 나뉩니다.

스키마누구의 관점인가내용
외부 스키마
(External)		일반 사용자·응용 프로그램내가 필요한 부분만 보이는 화면. 사람마다 여러 개 존재. 서브 스키마라고도 함
개념 스키마
(Conceptual)		조직 전체(DBA)데이터베이스 전체의 논리적 구조. 조직에 딱 하나만 존재. 그냥 "스키마"라고 하면 이것
내부 스키마
(Internal)		저장장치(시스템)데이터가 디스크에 실제로 어떻게 저장되는지(레코드 형식, 인덱스, 압축 등)
비유 — 아파트로 보면, 외부 스키마는 우리 집 도면(내가 사는 집만), 개념 스키마는 아파트 단지 전체 설계도(딱 한 장), 내부 스키마는 철근·배관이 실제로 어떻게 깔렸는지를 적은 시공도예요.
시험 포인트 — 개념 스키마는 조직에 하나, 외부 스키마는 여러 개. "데이터베이스 전체를 기술하며 하나만 존재하는 스키마는?" → 개념 스키마. 가장 많이 출제되는 문장입니다.

5. 데이터 독립성과 3단계 구조의 이유

스키마를 3장으로 나눈 진짜 이유는 데이터 독립성을 얻기 위해서예요. 독립성이란 한쪽을 바꿔도 다른 쪽을 고치지 않아도 되는 성질입니다.

독립성뜻
논리적 독립성개념 스키마가 바뀌어도(표에 컬럼 추가 등) 응용 프로그램은 그대로
물리적 독립성내부 스키마가 바뀌어도(디스크 교체, 인덱스 추가 등) 개념 스키마와 프로그램은 그대로
사상(Mapping) — 세 스키마를 서로 연결해 주는 대응 관계를 '사상'이라고 해요. 외부↔개념 연결이 외부/개념 사상(논리적 사상), 개념↔내부 연결이 개념/내부 사상(물리적 사상)입니다. 이 사상이 있어서 한쪽만 고쳐도 나머지가 무사할 수 있어요.

마지막으로 자주 나오는 용어 두 개를 정리합니다.

용어쉬운 뜻
인스턴스(Instance)스키마(설계도)에 따라 실제로 저장된 값. 설계도는 잘 안 바뀌지만 값은 수시로 바뀜
데이터 사전
(Data Dictionary)		DB에 어떤 표·컬럼·권한이 있는지 적어 둔 표. 시스템이 스스로 관리하므로 시스템 카탈로그라고도 함
시험 포인트 — "데이터에 대한 데이터(메타 데이터)를 저장한 시스템 테이블" = 데이터 사전(시스템 카탈로그). 사용자는 조회만 가능하고 직접 수정할 수 없다는 점이 함께 출제됩니다.

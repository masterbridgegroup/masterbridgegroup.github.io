어제(Day 48)는 단위 모듈과 통합 구현을 배웠어요. 딱 하나만 다시: 좋은 모듈은 결합도는 낮게, 응집도는 높게 만들고, 프로그램끼리 대화하는 IPC는 5종(공유 메모리·소켓·메시지 큐·파이프·RPC)이었죠. 오늘은 이번 주(Day 43~48) 내용을 표로 압축 정리한 뒤, 종합 테스트 15문제로 마무리합니다.

1. 탐색 알고리즘 성적표

탐색(Search, 찾기)은 많은 자료 속에서 원하는 값을 찾아내는 방법이에요. 시간 복잡도(빠른 정도를 나타내는 기호)를 같이 외우는 것이 핵심입니다.

방법어떻게 찾나시간 복잡도조건
순차 탐색
(선형 탐색)		처음부터 하나씩 끝까지 확인O(n)
평균 (n+1)/2회 비교		정렬 불필요
이진 탐색가운데를 보고 절반씩 버림O(log₂n)정렬 필수
이진 탐색 트리
(BST)		왼쪽은 작은 값, 오른쪽은 큰 값으로 내려감평균 O(log₂n)
최악 O(n)		트리가 한쪽으로 치우치면 느려짐
해싱주소를 계산해서 바로 찾아감O(1)충돌(Collision) 관리 필요
비유 — 순차 탐색은 책을 1쪽부터 넘기며 찾기, 이진 탐색은 사전을 반씩 펼쳐 찾기, 해싱은 사물함 번호를 계산해 바로 열기입니다.
시험 포인트 — 이진 탐색은 "반드시 정렬된 자료에만 쓸 수 있다"가 최다 출제 문장이고, 이진 탐색 트리를 중위 순회(왼쪽→루트→오른쪽)하면 오름차순으로 정렬되어 나온다는 점도 단골입니다.

2. 해싱 용어와 충돌 해결

해싱은 해싱 함수(주소를 계산해 주는 식)로 버킷(자료를 담는 칸)의 주소를 구하는 방식이에요. 용어를 정확히 구분해 두어야 합니다.

용어쉬운 뜻
버킷(Bucket)하나의 주소가 가리키는 저장 공간. 여러 개의 슬롯으로 이루어짐
슬롯(Slot)버킷 안에서 하나의 자료가 들어가는 칸
충돌(Collision)서로 다른 자료가 같은 주소를 받은 상태
동의어(Synonym)같은 주소를 받은 자료들의 집합
오버플로(Overflow)충돌이 생겼는데 버킷에 빈 슬롯이 없어 넣을 수 없는 상태

해싱 함수의 종류와 충돌 해결 방법도 짝지어 외워 둡시다.

구분내용
해싱 함수제산법(소수로 나눈 나머지 — 대표), 제곱법, 폴딩법(접어서 더하기), 기수 변환법, 대수적 코딩법, 숫자 분석법(계수 분석법)
충돌 해결개방 주소법(선형 탐사 — 빈 자리를 찾아 옆으로 이동), 체이닝(연결 리스트로 이어 붙임), 재해싱(다른 함수로 다시 계산)
시험 포인트 — "가장 널리 쓰이는 해싱 함수는?" → 제산법(Division). "충돌은 발생했지만 저장할 곳이 없는 상태는?" → 오버플로. 충돌과 오버플로를 바꿔치기한 보기가 자주 나옵니다.

3. 파일 구조와 DB 개요

파일 구조특징
순차 파일입력 순서대로 차례로 저장. 순차 접근만 가능, 공간 낭비 적음
색인 순차 파일
(ISAM)		목차(색인)를 따로 둠. 순차 접근 + 직접 접근 모두 가능
직접 파일
(해싱 파일)		해싱 함수로 주소를 계산해 바로 접근. 가장 빠름

데이터베이스(DB)는 여러 사람이 함께 쓰기 위해 통합해 저장한 데이터의 모음이고, 이를 관리해 주는 소프트웨어가 DBMS예요.

항목내용
DB의 4가지 특성통합된 데이터 · 저장된 데이터 · 공용 데이터 · 운영 데이터
DBMS 3대 필수 기능정의(구조 만들기) · 조작(넣고 찾고 고치기) · 제어(정확성·보안 유지)
스키마 3단계외부(사용자별 관점, 여러 개) · 개념(조직 전체 관점, 딱 하나) · 내부(실제 저장 방식)
시험 포인트 — 색인 순차 파일만 순차·직접 접근이 모두 된다는 문장, 그리고 개념 스키마는 조직에 단 하나라는 문장이 반복 출제됩니다.

4. 통합 구현·IPC·개발 도구

항목꼭 기억할 내용
단위 모듈기능 단위 최소 부품. 명세서 + 입·출력 기능 구현으로 구성
좋은 모듈결합도 낮게, 응집도 높게
통합 구현 흐름송신 → (중계 서버) → 수신. 중계 서버는 선택 사항
IPC 5종공유 메모리(공동 칠판) · 소켓(전화선) · 메시지 큐(사서함·비동기) · 파이프(수도관) · RPC(남의 함수 호출)
개발 도구IDE / 빌드(Ant·Maven·Gradle) / 형상 관리(Git·SVN) / 테스트(JUnit·Selenium) / 협업(Jira)
내일 예고 — Day 50부터는 형상 관리(소스 코드의 변경 이력을 관리하는 일)로 들어갑니다. 오늘 표의 "형상 관리 도구 = Git·SVN" 한 줄이 그 출발점이에요.
시험 포인트 — 이번 주 최우선 3문장: ① 이진 탐색은 정렬 필수, O(log₂n) ② 해싱은 O(1), 충돌·동의어·오버플로 구분 ③ DBMS 3대 기능은 정의·조작·제어.

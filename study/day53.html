빌드 자동화 — Ant·Maven·Gradle과 Jenkins

2026-08-25 · 오늘 배울 개념 5개 + 퀴즈 10문제 (약 1시간)

복습 한 스푼 🥄

어제(Day 52)는 SVN과 Git의 명령어를 배웠어요. 딱 하나만 다시: Git은 작업 트리 → 스테이지(add) → 지역 저장소(commit) → 원격 저장소(push) 순서로 흘러가고, pull = fetch + merge였죠. 오늘은 그렇게 모은 소스 코드를 실행 가능한 프로그램으로 자동 변환하는 빌드 자동화를 배웁니다.

1. 빌드란? — 소스 코드를 실행 파일로 만드는 일

빌드(Build)는 개발자가 쓴 소스 코드를 컴퓨터가 실행할 수 있는 형태로 바꾸고, 필요한 부품을 챙겨 하나의 결과물로 묶는 전체 과정이에요. 단순히 컴파일 하나만을 뜻하는 것이 아닙니다.

순서단계내용
①컴파일
(Compile)		사람이 쓴 코드를 기계어로 번역
②링크
(Link)		번역된 조각들과 라이브러리를 연결
③테스트
(Test)		자동 단위 테스트를 실행해 오류 확인
④패키징
(Packaging)		실행 파일과 자원을 하나의 묶음으로 포장 (예: jar, war)
⑤배포
(Deploy)		서버나 사용자에게 전달·설치
비유 — 라면을 끓이는 과정이 빌드예요. 면을 삶고(컴파일), 스프를 넣고(링크), 간을 보고(테스트), 그릇에 담고(패키징), 상에 내는(배포) 일이 한 번의 버튼으로 자동으로 되게 만드는 것이 빌드 자동화입니다.
시험 포인트 — "빌드 = 컴파일만"이라는 보기는 오답입니다. 빌드는 컴파일·링크·테스트·패키징·배포를 포함하는 전체 과정이라고 기억하세요.

2. 빌드 자동화 도구 — 왜 필요한가

사람이 매번 손으로 빌드하면 순서를 빠뜨리거나 실수하기 쉬워요. 빌드 자동화 도구는 이 과정을 스크립트(작업 순서를 적어 둔 파일)에 따라 자동 실행합니다.

이점설명
반복 작업 제거명령 한 번으로 매번 똑같은 순서대로 실행
휴먼 에러 감소사람이 순서를 빠뜨릴 여지를 없앰
의존성 자동 관리필요한 라이브러리를 스스로 내려받아 연결
빠른 오류 발견빌드할 때마다 테스트가 자동 실행되어 문제를 조기에 발견
의존성이란? — 내 프로그램이 동작하기 위해 반드시 필요한 다른 부품(라이브러리)을 말해요. "이 프로그램은 A 라이브러리에 의존한다"는 뜻입니다. Maven·Gradle의 가장 큰 장점이 이 의존성을 자동으로 챙겨 온다는 점이에요.
시험 포인트 — 빌드 자동화 도구의 3대 기능은 ① 빌드 실행 ② 의존성(라이브러리) 관리 ③ 테스트 자동 수행입니다.

3. Ant · Maven · Gradle 비교 — 빌드 3형제

도구설정 파일특징
Ant
(Another Neat Tool)		build.xml
(XML)		가장 오래된 자바 빌드 도구. 작업 순서를 직접 하나하나 적어야 함. 의존성 자동 관리 기능이 없음
Mavenpom.xml
(XML)		의존성 자동 관리가 핵심. 정해진 생애 주기(Life Cycle)에 따라 빌드. 인터넷의 중앙 저장소에서 라이브러리를 내려받음
Gradlebuild.gradle
(Groovy 기반 스크립트)		Ant와 Maven의 장점을 합친 최신 도구. 태스크(Task) 단위로 실행, 이전 빌드 결과를 재사용해 속도가 빠름. 안드로이드 앱의 표준 빌드 도구
한 줄 구분 — Ant는 수동 레시피(내가 순서를 다 적음), Maven은 정식 요리법(정해진 순서를 따르고 재료는 알아서 배달), Gradle은 스마트 주방(빠르고 유연하며 안드로이드 기본).
시험 포인트 — ① Ant는 의존성 관리 기능이 없다 ② Maven의 설정 파일은 pom.xml ③ Gradle은 Groovy 기반이며 안드로이드 기본 빌드 도구. 이 세 문장이 그대로 보기로 나옵니다.

4. Jenkins — 빌드를 대신 눌러 주는 서버

Jenkins(젠킨스)는 Java로 만든 오픈 소스 빌드 자동화 서버예요. 개발자가 소스를 커밋하면 Jenkins가 알아서 빌드와 테스트를 실행하고 결과를 알려 줍니다.

특징설명
웹 기반 관리브라우저 화면(GUI)에서 클릭으로 설정. 다루기 쉬움
형상 관리 연동Git·SVN 등 대부분의 도구와 연결 가능
서버에서 동작서블릿 컨테이너(Tomcat 등) 위에서 실행되는 서버형 도구
플러그인 확장필요한 기능을 플러그인으로 추가
비유 — 밥솥의 예약 취사 기능이에요. 쌀만 씻어 넣으면(커밋) 정해진 시각이나 조건에 알아서 밥을 짓고(빌드) 다 되면 알려 줍니다. 사람이 지켜보지 않아도 되죠.
시험 포인트 — "Java 기반의 오픈 소스이며, 웹 기반 GUI를 제공하고 대부분의 형상 관리 도구와 연동되는 빌드 자동화 도구는?" → Jenkins. 문장을 통째로 외워 두세요.

5. CI / CD — 계속 합치고 계속 배포한다

용어뜻
CI
(Continuous Integration,
지속적 통합)		개발자들이 고친 코드를 하루에도 여러 번 합치고 그때마다 자동 빌드·테스트. 문제를 작을 때 발견하는 것이 목적
CD
(Continuous Delivery/Deployment,
지속적 제공·배포)		테스트를 통과한 결과물을 자동으로 배포 가능한 상태로 만들거나 실제 서비스에 올림
왜 자꾸 합칠까? — 3개월 동안 각자 작업한 뒤 한 번에 합치면 충돌이 산더미처럼 쌓여요. 매일 조금씩 합치면 문제도 조금씩만 생깁니다. 이것이 CI의 핵심 아이디어예요.
시험 포인트 — CI의 목적은 "통합에서 생기는 문제를 조기에 발견"이고, 이를 실행하는 대표 도구가 Jenkins입니다. 내일(Day 54)은 완성된 제품을 사용자에게 전달하는 패키징을 배웁니다.

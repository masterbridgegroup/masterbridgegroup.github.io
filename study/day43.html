탐색 알고리즘 ① — 순차 탐색과 이진 탐색

2026-08-15 · 오늘 배울 개념 5개 + 퀴즈 10문제 (약 1시간)

복습 한 스푼 🥄

어제(Day 42)는 이번 주 자료구조와 정렬을 총정리했어요. 딱 하나만 다시: 퀵 정렬은 평균 O(n log n)이지만 최악에는 O(n²), 합병·힙 정렬은 최악에도 O(n log n)이었죠. 오늘부터는 '줄 세우기(정렬)'가 아니라 '찾기(탐색)'를 배웁니다. 정렬을 먼저 배운 이유가 오늘 바로 드러나요.

1. 탐색(Search)이란? — 원하는 자료를 찾아내기

탐색(Search)은 많은 데이터 중에서 내가 원하는 하나를 찾아내는 일이에요. 컴퓨터가 하는 일의 절반 이상이 사실 이 '찾기'입니다.

쉽게 말하면 — 전화번호부에서 '홍길동'을 찾는 일이에요. 첫 장부터 한 명씩 넘겨 보는 방법(순차 탐색)과, 가운데를 펼쳐 앞/뒤를 판단하며 좁혀 가는 방법(이진 탐색)이 있죠. 후자가 훨씬 빠르지만, 전화번호부가 이름순으로 정렬되어 있어야 가능해요.

탐색 방법은 크게 두 부류입니다.

구분방법정렬이 필요한가?
비교 기반 탐색순차 탐색, 이진 탐색, 보간 탐색, 피보나치 탐색순차 탐색만 불필요, 나머지는 필요
계산 기반 탐색해싱(Hashing)불필요 (주소를 계산해서 바로 감)
시험 포인트 — "정렬되어 있지 않아도 사용할 수 있는 탐색은?" → 순차 탐색(그리고 해싱). "반드시 정렬되어 있어야 하는 탐색은?" → 이진 탐색. 이 한 쌍이 가장 많이 출제됩니다.

2. 순차 탐색 (Sequential / Linear Search) — 처음부터 하나씩

순차 탐색은 자료의 맨 앞부터 끝까지 하나씩 비교하며 찾는 가장 단순한 방법이에요. 선형 탐색이라고도 합니다.

비유 — 서랍 10칸을 1번부터 차례로 다 열어 보는 것. 운 좋으면 1번에서 찾고(최선), 운 나쁘면 10번째에서 찾거나 아예 없죠(최악).

데이터가 n개일 때 비교 횟수를 따져 봅시다.

경우비교 횟수
최선(맨 앞에 있을 때)1회
평균(n+1)/2 회
최악(맨 뒤에 있거나 없을 때)n회

시간 복잡도는 O(n). 느리지만 정렬이 필요 없고 구현이 가장 쉽다는 게 장점이라, 데이터가 적을 때는 오히려 실용적이에요.

시험 포인트 — 순차 탐색의 평균 비교 횟수 (n+1)/2는 공식 그대로 출제됩니다. 자료가 100개면 평균 50.5회예요.

3. 이진 탐색 (Binary Search) — 반씩 잘라 버리기

이진 탐색은 정렬된 자료의 가운데 값과 찾는 값을 비교해서, 한 번 비교할 때마다 찾을 범위를 절반씩 버리는 방법이에요.

비유 — "1~100 사이 숫자 맞히기" 게임에서 50을 먼저 부르는 전략! "더 커요"라고 하면 1~50은 통째로 버리고 51~100만 남죠. 7번만 물어보면 100개 중 하나를 반드시 찾아냅니다.

동작 순서는 이렇습니다.

① 중간 위치 = (처음 + 끝) ÷ 2 (소수점 버림) → ② 중간 값과 찾는 값을 비교 → ③ 같으면 끝 / 찾는 값이 더 작으면 왼쪽 절반만 남김(끝 = 중간-1) / 더 크면 오른쪽 절반만 남김(처음 = 중간+1) → ④ 처음 ≤ 끝인 동안 반복

시험 포인트 — 중간 위치 계산식 (low + high) / 2와, 왼쪽을 택할 때 high = mid - 1, 오른쪽을 택할 때 low = mid + 1이 되는 것을 꼭 기억하세요. 계산 문제로 자주 나옵니다.

4. 이진 탐색 직접 해보기 + 속도

정렬된 자료 [10, 20, 30, 40, 50, 60, 70]에서 60을 찾아봅시다. (위치는 1~7번)

회차처음~끝중간 위치·값판단
1회1~74번 = 4060 > 40 → 오른쪽만 남김(5~7)
2회5~76번 = 60일치! 2번 만에 찾음 ✅

7개 자료를 순차 탐색하면 최악 7번 비교하지만, 이진 탐색은 최악 3번이면 끝나요. 시간 복잡도는 O(log₂n)입니다.

얼마나 빠른가 — 자료가 100만 개여도 이진 탐색은 약 20번 비교면 찾아냅니다(2²⁰ ≈ 100만). 순차 탐색은 평균 50만 번이죠. 이게 O(log n)의 힘이에요.

단점도 분명합니다. ① 미리 정렬되어 있어야 하고 ② 중간 위치를 바로 계산해야 하므로 배열처럼 임의 접근이 되는 구조여야 해요(연결 리스트에는 부적합). ③ 데이터가 자주 삽입·삭제되면 정렬을 다시 유지하는 비용이 듭니다.

시험 포인트 — "이진 탐색의 시간 복잡도는?" → O(log₂n). "이진 탐색의 전제 조건은?" → 자료가 정렬되어 있어야 한다. 이 두 개는 거의 매회 나옵니다.

5. 보간 탐색과 피보나치 탐색 — 이진 탐색의 사촌들

이진 탐색은 무조건 '가운데'를 보지만, 사전에서 '가'로 시작하는 단어를 찾을 때 우리는 가운데가 아니라 맨 앞쪽을 펼치죠. 이 아이디어를 쓴 게 보간 탐색입니다.

탐색다음에 볼 위치를 정하는 방법특징
이진 탐색항상 정확히 가운데가장 무난, O(log₂n)
보간 탐색
(Interpolation)		찾는 값의 크기에 비례해 위치를 추정값이 고르게 퍼져 있으면 이진 탐색보다 빠름
피보나치 탐색
(Fibonacci)		피보나치 수열(1,1,2,3,5,8…)로 구간을 나눔나눗셈 대신 덧셈·뺄셈만 사용
블록 탐색
(Block)		자료를 블록으로 묶어 블록 대표값만 먼저 비교색인(인덱스) 순차 탐색이라고도 함
한 줄 정리 — 보간 탐색 = 사전 펼치기(찾는 값이 앞쪽이면 앞쪽을 펼침), 피보나치 탐색 = 나눗셈 없는 이진 탐색.
시험 포인트 — "찾으려는 값의 위치를 비례식으로 추정하는 탐색" = 보간 탐색. "나눗셈을 사용하지 않고 덧셈·뺄셈만으로 탐색" = 피보나치 탐색. 용어와 한 줄 설명만 짝지어 두면 충분해요.

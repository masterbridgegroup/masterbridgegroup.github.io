해싱 ① — 계산해서 바로 찾아가는 마법

2026-08-17 · 오늘 배울 개념 5개 + 퀴즈 10문제 (약 1시간)

복습 한 스푼 🥄

어제(Day 44)는 이진 탐색 트리를 배웠어요. 딱 하나만 다시: BST는 왼쪽 < 루트 < 오른쪽 규칙을 지키는 트리이고, 중위 순회하면 오름차순으로 나왔죠. 하지만 BST도 결국 여러 번 비교를 해야 합니다. 오늘은 비교를 아예 하지 않고 단 한 번에 찾아가는 방법을 배웁니다.

1. 해싱(Hashing)이란? — 주소를 계산해 버린다

지금까지 배운 탐색은 모두 "비교"를 했어요. 순차 탐색은 n번, 이진 탐색은 log n번 비교했죠. 해싱은 완전히 다른 발상입니다. 찾는 값 자체를 계산해서 저장 위치(주소)를 바로 알아내는 방법이에요.

쉽게 말하면 — 아파트 우편함을 떠올려 보세요. '502호 우편물'을 찾을 때 1호부터 다 열어 보지 않죠. 호수 = 우편함 번호라는 규칙이 있으니 곧장 502번 함으로 갑니다. 해싱은 이 '규칙으로 주소 계산하기'를 데이터에 적용한 거예요.

용어를 정리하면 이렇습니다.

용어쉬운 뜻
키(Key)찾을 때 기준이 되는 값 (예: 학번, 주민번호, 상품코드)
해시 함수(Hash Function)키를 넣으면 저장 위치를 계산해 주는 계산 규칙
해시값 / 해시 주소해시 함수가 뱉어낸 결과 = 저장할 위치 번호
해시 테이블(Hash Table)데이터가 실제로 담기는 표(저장 공간)
시험 포인트 — 해싱의 평균 시간 복잡도는 O(1)입니다. 자료가 100만 개여도 계산 한 번으로 찾으니까요. "탐색 시간이 자료의 개수와 무관한 방법은?" → 해싱.

2. 버킷과 슬롯 — 해시 테이블의 구조

해시 테이블은 버킷과 슬롯이라는 2단 구조로 되어 있어요.

비유 — 아파트 우편함 한 칸이 버킷(Bucket)이고, 그 칸 안에 편지를 여러 통 꽂을 수 있는 자리가 슬롯(Slot)이에요. 버킷 하나에 슬롯이 3개면, 같은 주소가 나온 데이터 3개까지는 사이좋게 들어갈 수 있죠.

여기서 해싱의 유일한 골칫거리가 등장합니다.

용어무슨 일이 벌어진 것인가
충돌(Collision)서로 다른 키인데 해시 함수가 같은 주소를 내놓은 상황
동거자(Synonym)충돌이 일어나 같은 주소를 배정받은 키들을 부르는 말
오버플로(Overflow)충돌이 계속 일어나 그 버킷의 슬롯이 다 차서 더 넣을 수 없는 상황
시험 포인트 — 충돌 ≠ 오버플로를 구분하는 문제가 자주 나옵니다. 주소가 겹친 것이 충돌, 겹친 데다 자리까지 없어진 것이 오버플로. 슬롯이 여러 개면 충돌이 나도 오버플로는 아닐 수 있어요.

3. 해시 함수 ① — 제산법과 중간 제곱법

좋은 해시 함수는 주소를 골고루 흩뿌려 충돌을 줄이는 함수예요. 시험에 나오는 방법을 하나씩 봅시다.

제산법(Division Method) — 가장 많이 쓰이고 가장 많이 출제되는 방법입니다. 키를 어떤 수로 나눈 나머지를 주소로 씁니다.

계산해 보기 — 버킷이 11개(0~10번)이고 키가 125라면, 125 ÷ 11 = 11 … 나머지 4. 따라서 4번 버킷에 저장! 나머지는 절대 0~10을 벗어나지 않으니 언제나 테이블 안쪽 주소가 나와요.

나누는 수는 보통 소수(1과 자기 자신만으로 나누어지는 수: 11, 13, 17…)를 씁니다. 소수로 나누면 나머지가 더 고르게 퍼져 충돌이 줄어들기 때문이에요.

중간 제곱법(Mid-square) — 키를 제곱한 뒤 가운데 몇 자리를 주소로 씁니다.

계산해 보기 — 키가 123이면 123² = 15129. 가운데 두 자리 51을 주소로 사용! 제곱을 하면 모든 자릿수가 서로 영향을 주므로, 앞자리만 비슷한 키들도 잘 흩어져요.
시험 포인트 — "키를 소수로 나눈 나머지를 주소로 사용" = 제산법(나눗셈법). 이 한 문장이 가장 많이 출제됩니다.

4. 해시 함수 ② — 폴딩·기수 변환·숫자 분석

방법계산 방식예시
폴딩법
(중첩법, Folding)		키를 같은 길이로 잘라 접어서 더함키 123456 → 12+34+56 = 102 → 주소 02
기수 변환법
(Radix)		키의 진법을 바꾼 뒤 필요한 자릿수만 사용10진수 키를 11진수로 바꿔 씀
숫자 분석법
(계수 분석법)		키들의 각 자릿수를 조사해, 값이 고르게 분포한 자리만 골라 씀학번 앞 두 자리는 입학연도로 모두 같으니 버리고 뒷자리만 사용
무작위법
(Random)		난수(무작위 수)를 발생시켜 주소로 사용-
이름으로 외우기 — 폴딩은 fold(접다) → 잘라서 더하기. 기수는 진법 → 진법 바꾸기. 숫자 분석은 자릿수를 분석해서 좋은 자리만 뽑기. 이름과 뜻이 그대로 연결돼요.
시험 포인트 — "키를 여러 부분으로 나누어 더하거나 XOR한 값을 주소로 사용" = 폴딩법(중첩법). "각 자릿수의 분포를 분석해 고른 자리를 선택" = 숫자 분석법.

5. 해싱은 언제 쓰고, 무엇을 포기하는가

해싱의 장단점을 정리하면 이렇습니다.

장점단점
탐색이 O(1) — 자료가 많아도 속도가 거의 일정충돌·오버플로 처리가 반드시 필요
정렬이 필요 없음저장 순서가 없어 순서대로 출력·범위 검색이 어려움
삽입·삭제도 빠름테이블 공간을 넉넉히 잡아야 해 메모리 낭비 가능
언제 무엇을 쓸까 — "이 학번의 학생 정보 하나만 딱 찾고 싶다" → 해싱. "성적 상위 10명, 또는 80점~90점 구간 학생" 같은 순서·범위가 필요하면 → 정렬·트리(BST·B-트리). 그래서 데이터베이스 인덱스는 해시가 아니라 B-트리를 주로 씁니다.
시험 포인트 — 탐색 방법별 시간 복잡도를 한 줄로 묶어 두세요. 순차 탐색 O(n) / 이진 탐색·BST O(log₂n) / 해싱 O(1). 표로 묻는 문제가 나옵니다.

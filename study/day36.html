어제(Day 35)로 1과목을 졸업했어요! 딱 하나만 다시: 좋은 설계의 황금률은 결합도(모듈 사이 의존)는 낮게, 응집도(모듈 안 뭉침)는 높게였죠. 오늘부터는 2과목 '소프트웨어 개발' — 프로그램이 데이터를 담고 정리하는 방법인 자료구조부터 시작합니다.

1. 자료구조란? — 데이터를 담는 그릇

자료구조(데이터를 저장하고 정리하는 방식)는 한마디로 데이터를 담는 그릇의 모양이에요. 그릇 모양에 따라 넣기·꺼내기·찾기의 속도가 달라집니다.

비유 — 옷을 서랍장에 개어 넣으면 찾기 쉽고, 빨래 바구니에 던져 넣으면 넣기는 빠르지만 찾기가 힘들죠. 어떤 그릇을 쓰느냐가 프로그램의 성능을 좌우해요.

자료구조는 크게 둘로 나눠요.

분류모양종류
선형 구조한 줄로 서 있음리스트(배열·연결 리스트), 스택, 큐, 데크
비선형 구조가지를 치며 퍼짐트리, 그래프
시험 포인트 — "다음 중 선형 구조가 아닌 것은?" 이 단골 문제예요. 답은 거의 항상 트리 또는 그래프입니다.

2. 배열 (Array) — 번호 붙은 사물함

배열은 같은 종류의 데이터를 연속된 공간에 번호(인덱스)를 붙여 나란히 저장하는 구조예요. 인덱스는 보통 0번부터 시작합니다.

비유 — 학교 사물함! 3번 사물함이라고 하면 바로 달려가 열 수 있듯, 배열은 인덱스만 알면 즉시 접근할 수 있어요(빠른 접근).

단점도 있어요. 중간에 데이터를 끼워 넣거나 빼려면 뒤의 데이터를 전부 밀거나 당겨야 해서 삽입·삭제가 느립니다. 또 사물함 개수(크기)를 처음에 정하면 바꾸기 어려워요.

시험 포인트 — 배열 = 접근(읽기) 빠름, 삽입·삭제 느림, 크기 고정, 연속 공간, 기억 장소 낭비 가능. 이 특징 조합을 묻습니다.

3. 연결 리스트 (Linked List) — 손잡고 있는 기차

연결 리스트는 데이터를 담은 칸(노드)들이 다음 칸이 어디 있는지 주소(포인터)로 가리키며 사슬처럼 이어진 구조예요. 공간이 연속일 필요가 없습니다.

비유 — 기차! 객차(노드)마다 "다음 객차는 저기"라는 연결 고리(포인터)가 있어요. 중간에 객차 하나를 끼우려면 연결 고리 2개만 바꾸면 끝 — 그래서 삽입·삭제가 빠릅니다.

대신 3번째 데이터를 찾으려면 1번부터 차례로 타고 가야 해서 접근(찾기)은 느려요. 또 포인터를 저장할 공간이 추가로 필요합니다.

시험 포인트 — 연결 리스트 = 삽입·삭제 빠름(포인터만 변경), 접근 느림(순차 탐색), 포인터용 추가 공간 필요. 배열과 정반대로 기억하세요.

4. 배열 vs 연결 리스트 — 최종 비교표

비교배열연결 리스트
저장 공간연속된 공간흩어져도 OK (포인터로 연결)
접근(읽기)빠름 (인덱스 즉시 접근)느림 (처음부터 순서대로)
삽입·삭제느림 (뒤 데이터 이동)빠름 (포인터만 변경)
크기고정유연하게 변경 가능
추가 공간필요 없음포인터 공간 필요
고르는 법 — 읽기(조회)가 많으면 배열, 넣고 빼기가 많으면 연결 리스트가 유리해요.

5. 빅오 표기법 맛보기 — 알고리즘의 성적표

앞으로 정렬·탐색을 배울 때 O(n) 같은 기호가 계속 나와요. 빅오(Big-O) 표기법은 데이터가 n개일 때 일이 얼마나 늘어나는지를 나타내는 성적표입니다.

표기느낌비유 (책 n권에서 찾기)
O(1)즉시 (데이터가 늘어도 한 번에)몇 번째 칸인지 알고 바로 꺼냄
O(log n)매우 빠름 (절반씩 줄임)사전에서 반씩 펼쳐가며 찾기
O(n)보통 (하나씩 전부 확인)첫 권부터 끝까지 넘겨보기
O(n²)느림 (전부 × 전부 비교)모든 책을 서로 짝지어 비교
시험 포인트 — 배열의 인덱스 접근은 O(1), 연결 리스트의 탐색은 O(n)이에요. 다음 주 정렬에서 O(n²)와 O(n log n)이 주인공으로 나옵니다.

Git과 SVN — 실제로 쓰는 명령어

2026-08-24 · 오늘 배울 개념 5개 + 퀴즈 10문제 (약 1시간)

복습 한 스푼 🥄

어제(Day 51)는 버전 관리 도구의 3가지 방식을 배웠어요. 딱 하나만 다시: 공유 폴더 = RCS·SCCS, 클라이언트/서버 = CVS·SVN, 분산 저장소 = Git이었죠. 오늘은 가장 많이 쓰이는 두 도구 SVN과 Git이 실제로 어떤 명령으로 움직이는지 살펴봅니다. 명령어 이름을 기능과 짝지어 묻는 문제가 나옵니다.

1. SVN(Subversion)의 특징

SVN은 중앙 서버 한 곳에 저장소를 두는 도구예요. 아파치 소프트웨어 재단에서 만들어 공개했습니다.

특징설명
중앙 집중식저장소가 서버에 하나. 모든 개발자가 이곳에 접속
리비전 번호누가 커밋하든 저장소 전체의 번호가 1씩 올라감 (1 → 2 → 3 …)
파일 잠금 가능이미지처럼 합칠 수 없는 파일은 잠금(Lock)을 걸어 한 사람만 수정
디렉터리 관리파일뿐 아니라 폴더의 이동·이름 변경 이력도 관리
비유 — 회사 공용 서버의 문서 번호와 같아요. 누가 어떤 문서를 수정하든 "제32차 개정"처럼 회사 전체의 개정 번호가 하나씩 올라갑니다.
시험 포인트 — SVN의 리비전 번호는 파일별로 따로 붙는 것이 아니라 저장소 전체 기준으로 증가합니다. 이 점이 오답 보기로 자주 등장합니다.

2. SVN 주요 명령어와 저장소 구조

명령하는 일
import빈 저장소에 처음으로 파일을 넣음
checkout저장소의 파일을 내 작업 공간으로 꺼내 옴 (관리 정보 포함)
export버전 관리 정보 없이 순수 파일만 꺼내 옴 (배포용)
add새로 만든 파일을 관리 대상에 등록
commit변경 내용을 저장소에 반영 (리비전 번호 증가)
update저장소의 최신 내용을 내려받아 동기화
diff변경된 차이점만 비교
info현재 작업 공간의 정보 확인
revert수정한 내용을 취소하고 원래대로 되돌림

SVN 저장소는 보통 폴더 세 개로 구성해요.

폴더용도
trunk주된 개발이 이루어지는 몸통
branches따로 갈라 작업하는 가지들을 모아 둠
tags출시 시점 등을 이름표 붙여 보관 (수정하지 않음)
시험 포인트 — checkout과 export의 차이가 핵심입니다. checkout은 버전 관리 정보를 함께 가져와 이후 커밋이 가능하고, export는 순수한 파일만 가져와 배포용으로 씁니다.

3. Git의 특징 — 두 개의 저장소

Git은 리누스 토르발스가 리눅스 개발을 위해 만든 분산 버전 관리 도구예요. 가장 큰 특징은 저장소가 두 개라는 점입니다.

저장소위치와 역할
지역(로컬) 저장소내 컴퓨터에 있는 저장소. 혼자서 커밋하고 이력을 쌓음
원격 저장소서버(예: GitHub)에 있는 저장소. 팀원과 공유
비유 — 개인 일기장(지역 저장소)에 매일 기록하고, 정리된 내용만 학급 문집(원격 저장소)에 실어 보내는 것과 같아요. 일기는 인터넷 없이도 쓸 수 있으니 SVN보다 자유롭습니다.
시험 포인트 — Git은 인터넷이 연결되지 않은 상태에서도 지역 저장소에 커밋할 수 있다는 점이 SVN과의 결정적 차이입니다.

4. Git의 3단계 영역 — 작업 → 준비 → 저장

Git에서 파일은 세 칸을 차례로 지나갑니다. 이 구조를 이해하면 명령어가 자연스럽게 외워져요.

순서영역설명
①작업 트리
(Working Tree)		실제로 파일을 고치는 폴더
②스테이지
(Staging Area, 인덱스)		커밋할 것만 골라 담아 두는 대기 장소
③지역 저장소커밋이 이력으로 확정되어 쌓이는 곳
비유 — 장을 볼 때 ① 진열대에서 물건을 고르고(작업 트리) ② 장바구니에 담고(스테이지) ③ 계산을 끝내면 영수증이 남죠(커밋). add는 장바구니에 담기, commit은 계산하기입니다.
시험 포인트 — Git에만 있는 특징이 바로 이 스테이징 영역(Staging Area)입니다. "커밋할 대상을 선별해 임시로 저장하는 영역"의 답은 스테이지/인덱스예요.

5. Git 주요 명령어

명령하는 일
git init현재 폴더에 새 지역 저장소를 생성
git clone원격 저장소를 통째로 복제해 내 컴퓨터로 가져옴
git add변경한 파일을 스테이지에 올림
git commit스테이지의 내용을 지역 저장소에 확정 저장
git push지역 저장소의 커밋을 원격 저장소로 올림
git fetch원격 저장소의 변경 내용을 내려받기만 함(아직 합치지 않음)
git pull원격의 내용을 내려받아 바로 합침 (fetch + merge)
git branch브랜치를 만들거나 목록을 확인
git checkout다른 브랜치로 이동
git merge다른 브랜치의 내용을 현재 브랜치에 합침
git log커밋 이력을 확인
한 흐름으로 — clone(복제) → 수정 → add(담기) → commit(확정) → push(올리기). 남이 올린 내용을 받을 때는 pull. 이 다섯 단어만 알면 실무 흐름이 끝납니다.
시험 포인트 — fetch와 pull의 차이(pull = fetch + merge)와 push의 방향(지역 → 원격)이 대표 출제 포인트입니다. 두 사람이 같은 줄을 고쳤을 때 생기는 충돌(Conflict)은 개발자가 직접 내용을 확인해 해결해야 한다는 점도 기억하세요.

탐색 알고리즘 ② — 이진 탐색 트리와 균형 트리

2026-08-16 · 오늘 배울 개념 5개 + 퀴즈 10문제 (약 1시간)

복습 한 스푼 🥄

어제(Day 43)는 순차 탐색과 이진 탐색을 배웠어요. 딱 하나만 다시: 이진 탐색은 정렬된 자료에서만 쓸 수 있고, 한 번 비교할 때마다 범위가 절반으로 줄어 O(log₂n)이었죠. 그런데 이진 탐색의 약점은 자료를 새로 넣거나 뺄 때마다 정렬을 다시 유지해야 한다는 것이었어요. 오늘은 그 약점을 해결한 자료구조를 배웁니다.

1. 이진 탐색 트리(BST)란? — 규칙 있는 나무

이진 탐색 트리(Binary Search Tree)는 이름 그대로 이진 트리(자식이 최대 2명)에 탐색을 위한 규칙을 하나 얹은 자료구조예요. 규칙은 단 하나입니다.

BST의 단 하나의 규칙 — 어떤 노드를 기준으로, 왼쪽 자손은 모두 나보다 작고, 오른쪽 자손은 모두 나보다 크다. 이 규칙이 모든 노드에서 지켜져야 해요.

예를 들어 50이 뿌리(루트)라면, 왼쪽 가지에는 30·20·40처럼 50보다 작은 값만, 오른쪽 가지에는 70·60·80처럼 50보다 큰 값만 들어갑니다.

왜 이렇게 만들까요? 값 하나를 찾을 때 뿌리에서 시작해 크다/작다만 판단하면 한쪽 가지를 통째로 버릴 수 있어서예요. 어제 배운 이진 탐색과 완전히 같은 원리인데, 이번엔 배열이 아니라 트리로 구현한 거죠.

시험 포인트 — "왼쪽 서브트리의 모든 값 < 루트 < 오른쪽 서브트리의 모든 값"이라는 문장이 BST의 정의입니다. 보기에서 이 문장을 골라내는 문제가 나와요.

2. BST에 값을 넣어 보기 (삽입)

빈 트리에 50, 30, 70, 20, 40, 60을 순서대로 넣어 봅시다. 넣는 방법은 "뿌리부터 크다/작다를 따라 내려가서, 빈 자리에 매달기"입니다.

넣는 값내려가는 길결과
50트리가 비어 있음루트가 됨
3050보다 작다 → 왼쪽50의 왼쪽 자식
7050보다 크다 → 오른쪽50의 오른쪽 자식
2050보다 작다 → 왼쪽(30), 30보다 작다 → 왼쪽30의 왼쪽 자식
4050보다 작다 → 왼쪽(30), 30보다 크다 → 오른쪽30의 오른쪽 자식
6050보다 크다 → 오른쪽(70), 70보다 작다 → 왼쪽70의 왼쪽 자식
여기서 중요한 성질! — 이렇게 만든 BST를 중위 순회(왼쪽 → 루트 → 오른쪽)하면 20, 30, 40, 50, 60, 70 — 값이 작은 것부터 순서대로 나옵니다. 즉 BST의 중위 순회 결과는 항상 오름차순 정렬이에요.
시험 포인트 — "이진 탐색 트리를 중위 순회하면?" → 오름차순으로 정렬된 결과. 단골 문제입니다.

3. BST에서 찾기와 지우기

탐색은 삽입과 똑같아요. 뿌리부터 크다/작다를 비교해 한쪽으로만 내려갑니다. 트리의 높이만큼만 비교하면 되니 평균 O(log₂n)이에요.

삭제는 지우려는 노드의 자식 수에 따라 세 가지 경우로 나뉩니다.

자식 수처리 방법
0개 (잎 노드)그냥 떼어냄
1개자식을 내 자리로 끌어올림
2개왼쪽 서브트리의 가장 큰 값 또는 오른쪽 서브트리의 가장 작은 값을 내 자리에 올림
왜 그 값일까 — 내 자리에 올 수 있는 값은 "나와 가장 가까운 값"이어야 BST 규칙이 깨지지 않아요. 나보다 조금 작은 값(왼쪽에서 최대) 또는 조금 큰 값(오른쪽에서 최소)이 바로 그것이죠.
시험 포인트 — BST에서 가장 작은 값은 왼쪽으로만 계속 내려간 끝, 가장 큰 값은 오른쪽으로만 계속 내려간 끝에 있습니다.

4. BST의 치명적 약점 — 한쪽으로 기울어진 트리

BST는 평균 O(log₂n)이지만, 최악의 경우 O(n)까지 느려져요. 언제 그럴까요?

최악의 상황 — 빈 트리에 10, 20, 30, 40, 50처럼 이미 정렬된 순서로 넣으면? 모두 오른쪽 자식으로만 매달려서 일직선 막대기가 됩니다. 이러면 트리가 아니라 그냥 연결 리스트와 같아서, 찾을 때 n번을 다 훑어야 해요.

이렇게 한쪽으로 쏠린 트리를 편향 트리(Skewed Tree) 또는 사향 트리라고 불러요. 트리 탐색이 빠른 이유는 '높이가 낮아서'인데, 편향 트리는 높이가 n-1이 되어 장점이 사라집니다.

시험 포인트 — "이진 탐색 트리의 최악 시간 복잡도는?" → O(n). 원인은 편향 트리이고, 이미 정렬된 자료를 순서대로 삽입할 때 발생합니다.

5. 균형 트리 — 기울어지면 스스로 바로잡는다

편향 문제를 막기 위해, 삽입·삭제할 때마다 스스로 모양을 바로잡아 높이를 낮게 유지하는 트리들이 만들어졌어요. 이를 균형 이진 탐색 트리라고 합니다.

이름균형을 잡는 방법주요 쓰임
AVL 트리왼쪽·오른쪽 높이 차이를 -1, 0, 1만 허용. 벗어나면 회전(Rotation)으로 바로잡음탐색이 아주 많은 경우
레드-블랙 트리노드에 빨강·검정 색을 부여하고 색 규칙으로 균형 유지삽입·삭제가 잦은 경우
B-트리 / B+트리한 노드에 여러 값과 여러 자식을 두어 높이를 매우 낮게 유지데이터베이스 인덱스, 파일 시스템
AVL의 균형 인수 — 어떤 노드의 (왼쪽 높이 − 오른쪽 높이)를 균형 인수(Balance Factor)라고 해요. 이 값이 -1·0·1 중 하나면 균형, 절댓값이 2 이상이면 불균형이라 회전을 실시합니다.
시험 포인트 — ① AVL 트리는 균형 인수의 절댓값이 1 이하여야 한다 ② 균형이 깨지면 회전으로 복구한다 ③ B-트리는 데이터베이스 인덱스에 쓰인다 — 세 문장만 기억하면 충분합니다. B-트리는 3과목(데이터베이스)에서 다시 만나요.

형상 관리 ② — 버전 관리 도구 3가지 방식

2026-08-23 · 오늘 배울 개념 5개 + 퀴즈 10문제 (약 1시간)

복습 한 스푼 🥄

어제(Day 50)는 형상 관리의 개념을 배웠어요. 딱 하나만 다시: 형상 관리 4대 활동은 식별 → 통제 → 감사 → 기록("식·통·감·기")이고, 변경 통제의 기준이 되는 저장 시점을 베이스라인이라고 불렀죠. 오늘은 이 형상 관리를 실제로 해 주는 버전 관리 도구가 어떤 방식으로 작동하는지 배웁니다.

1. 버전 관리란? — 저장소에 모아 두고 꺼내 쓰기

버전 관리(Version Control)는 소스 코드와 문서의 변경 내용을 시간 순서대로 저장해 두고, 필요할 때 특정 시점으로 되돌릴 수 있게 하는 일이에요. 형상 관리 중 형상 통제를 실제로 실행하는 도구가 바로 버전 관리 도구입니다.

모든 버전 관리 도구에는 두 개의 공간이 있어요.

공간뜻
저장소
(Repository)		모든 버전과 변경 이력이 보관되는 중앙 창고
작업 공간
(Working Copy)		내 컴퓨터에 꺼내 와서 실제로 고치는 사본
비유 — 도서관(저장소)에서 책을 대출해 집에서 보고(작업 공간), 다 보면 반납하는 흐름과 같아요. 꺼내 오는 것이 체크아웃, 고친 것을 돌려 넣는 것이 체크인/커밋입니다.
시험 포인트 — 버전 관리 도구의 핵심 목적은 ① 변경 이력 추적 ② 이전 버전 복구 ③ 여러 사람의 동시 작업입니다. "저장 공간을 절약한다"는 목적이 아닙니다.

2. 공유 폴더 방식 — 한 폴더에 모아 두기

가장 원시적인 방식이에요. 개발자가 하루 작업이 끝나면 파일을 공유 폴더에 복사해 두고, 담당자가 그 파일들을 모아 검사한 뒤 관리합니다.

항목내용
대표 도구RCS(Revision Control System), SCCS(Source Code Control System)
특징RCS는 여러 사람이 동시에 수정하지 못하도록 파일을 잠그는(Lock) 방식을 사용
단점담당자가 수동으로 확인해야 하고, 파일이 사라지거나 덮어써질 위험이 있음
비유 — 학교 숙제를 교실 뒤 제출함에 넣어 두고 반장이 걷어 가는 방식이에요. 편하지만 누가 남의 숙제를 가져가도 알 수 없죠. RCS의 "잠금"은 한 번에 한 사람만 연필을 쥘 수 있게 만든 규칙입니다.
시험 포인트 — RCS는 파일을 잠가 동시 수정을 원천적으로 막는다는 설명이 그대로 출제됩니다. RCS·SCCS는 공유 폴더 방식임을 기억하세요.

3. 클라이언트/서버 방식 — 중앙 서버 하나에 모으기

중앙 서버에 저장소가 하나 있고, 개발자들은 각자의 컴퓨터(클라이언트)에서 그 서버에 접속해 파일을 꺼내 오고 돌려 넣습니다.

항목내용
대표 도구CVS, SVN(Subversion), Clear Case, CMVC, Perforce
장점모든 개발자의 작업 내용을 서버에서 한눈에 관리. 누가 무엇을 고쳤는지 즉시 확인
단점서버에 문제가 생기면 모두 작업이 멈춤. 네트워크 연결이 필수
비유 — 회사에 공용 프린터 서버가 하나 있는 것과 같아요. 모두가 그 서버를 거치니 관리가 편하지만, 서버가 고장 나면 아무도 일을 못 합니다.
시험 포인트 — SVN(Subversion)은 클라이언트/서버 방식의 대표이고, 저장소가 중앙에 하나라는 점이 핵심입니다. "SVN은 분산 저장소 방식이다"라는 보기는 오답입니다.

4. 분산 저장소 방식 — 내 컴퓨터에도 저장소가 있다

중앙 저장소뿐 아니라 개발자 각자의 컴퓨터에도 완전한 저장소 사본을 갖습니다. 먼저 자기 저장소에 저장(커밋)하고, 나중에 중앙 저장소와 동기화해요.

항목내용
대표 도구Git, Mercurial, Bazaar, Bitkeeper, GNU arch, Plastic SCM
장점인터넷이 끊겨도 혼자 작업 가능, 중앙 서버가 고장 나도 이력이 남아 있어 안전
단점개념이 다소 복잡하고 저장 공간을 더 많이 차지함
비유 — 도서관 책을 빌리는 게 아니라 도서관 전체를 복사해 집에 두는 방식이에요. 도서관이 문을 닫아도 집에서 계속 읽을 수 있죠. 이것이 Git이 전 세계 표준이 된 이유입니다.
시험 포인트 — 세 방식의 도구 분류는 매년 출제되는 단골입니다. 공유 폴더 = RCS·SCCS / 클라이언트·서버 = CVS·SVN·Clear Case / 분산 = Git·Mercurial·Bitkeeper. 이 한 줄만 외워도 한 문제는 맞습니다.

5. 버전 관리 공통 용어 — 시험에 이름으로 나온다

용어쉬운 뜻
가져오기(Import)아무것도 없는 빈 저장소에 처음으로 파일을 넣음
체크아웃(Check-Out)저장소에서 파일을 내 컴퓨터로 꺼내 옴
체크인(Check-In)고친 파일을 저장소로 다시 올림
커밋(Commit)변경 내용을 확정해 저장. 충돌이 있으면 알려 줌
동기화(Update)저장소의 최신 내용을 내 작업 공간에 반영
리비전(Revision)변경할 때마다 자동으로 붙는 버전 번호
트렁크(Trunk)나무의 몸통 — 개발의 중심 줄기가 되는 소스
브랜치(Branch)나무의 가지 — 몸통을 건드리지 않고 따로 갈라 작업하는 공간
머지(Merge)갈라진 가지를 다시 몸통에 합침
태그(Tag)특정 시점에 이름표를 붙임 (예: v1.0 출시본)
디프(Diff)두 버전의 차이만 뽑아 비교
나무로 기억하기 — 트렁크(몸통) → 브랜치(가지) → 머지(다시 합침). 새 기능을 실험할 때는 가지를 뻗어 안전하게 시도하고, 잘 되면 몸통에 합칩니다.
시험 포인트 — 가장 많이 나오는 짝은 "체크아웃 = 꺼내 오기", "체크인 = 올리기", "트렁크 = 주된 개발 줄기", "브랜치 = 분리된 작업 공간"입니다. 내일(Day 52)은 Git과 SVN의 실제 명령어를 봅니다.
